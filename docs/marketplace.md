Practical checklist to make the Pancho++ listing convert better. Screenshots and
GIFs are the single biggest lever: most users decide from the visuals, not the text.

## Screenshots

The screenshots and GIFs in `README.md` are generated by the capture harness, not
taken by hand. It launches a real VS Code (Extension Development Host) with
remote debugging, drives the UI through the Chrome DevTools Protocol and saves
the images under `images/`. It works on **Wayland** (where no system screenshot
tool can see the window) and never captures the desktop, so no personal data
leaks into the listing.

```bash
npm run capture                              # all scenes → images/
npm run capture -- --only=command-hub        # a single scene
npm run capture -- --gif                     # also record the GIF scenes
npm run capture -- --no-build                # skip `npm run bundle`
```

Scenes live in `scripts/capture/scenes.mjs` (add new ones there). The demo
workspace is copied to a throwaway profile outside the repo, and favorites and
pipelines are seeded so the UI looks populated; keep it theme-neutral (the
default dark theme is used). Keep each GIF under ~2 MB.

## Notes

- Keep everything **theme-neutral**: capture in the default dark theme, which is
  what most users run.
- Do not include personal data in screenshots (paths, tokens, emails).
- Prefer the default font and the default layout; avoid custom themes that make the
  UI look like a different product.
